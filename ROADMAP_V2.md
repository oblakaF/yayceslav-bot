# Яйцеслав V2 — дорожная карта и текущий статус

Обновлено: 2026-08-18
Рабочая ветка: `feature/human-yayceslav-v2`

Этот файл фиксирует текущий релизный статус. `DONE (code)` означает, что код реализован; `PASS (CI)` — полный workflow завершился зелёным; `CONFIRMED (runtime)` — поведение проверено живым Railway/Telegram.

## 1. Реализовано

### Gemini / ответы
- Основной `gemini-3.6-flash`, автоматический fallback на `gemini-3.1-flash-lite` при HTTP 429.
- Тот же запрос после 429 сразу повторяется на 3.1; 3.6 пробуется снова через 30 минут.
- Cooldown хранится на Railway Volume.
- Hostile/challenge compact guard: короткие ответы без лекционных простыней.
- Grammar-nazi: 25% как дополнительный вариант только при реальной ошибке в коротком несерьёзном сообщении.
- Rate-limit style guard скрывает технический текст ожидания.
- Primitive compact guard для простых запросов (`2+2`, `9*99`, `э`, `ну`, `чё`): ответ примерно до 110 символов; арифметический результат идёт первым.
- Primitive guard гарантированно загружается через ранний импорт `adaptation_cache.py`, то есть применяется и к primary, и к fallback Gemini.

### Голосовые
- Входящее аудио понимается Gemini напрямую без отдельной обязательной расшифровки.
- Голосовой ответ ограничен примерно 180 символами.
- Псевдотаймкоды удаляются.
- В конфликте допускается короткая многоуровневая шутка setup → verdict → send-off.
- Серьёзные темы не переводятся в издёвку.

### Реакции / пассивное поведение
- Частота Telegram emoji reactions снижена относительно прежней настройки.
- Random drops не создают независимый дополнительный спам-канал.
- Сохранены cooldown и ограничения hard-mode.

### Титулы
- Активные V2-пулы титулов вынесены отдельно.
- `/title` и `/title_status` зарегистрированы.
- Автоматический титул дня — только группы, окно после 18:00 МСК, scheduler раз в 60 секунд.
- Один автоматический титул на чат в сутки; кандидаты — участники, которые реально писали в этот день.
- Победитель хранится в SQLite; `PRIMARY KEY(chat_id, date)` не допускает второго победителя в тот же день.
- Повторная инициализация БД после рестарта не должна стирать назначение.
- Если отправка объявления упала, scheduler повторяет объявление того же победителя, а не выбирает нового.

### Стикерпак
- Официальный набор: `https://t.me/addstickers/yayceslav_stickers`.
- Финальный текущий размер пака: **37 стикеров**.
- Порядок всех 37 зафиксирован в `sticker_engine.py` и используется для live catalog mapping.
- Старый `ИДИ ЛЕСОМ` удалён; вместо него `ИДИ НА ХУЙ!`.
- `sticker_engine.py`: смысл каждого стикера + событие → допустимые стикеры.
- `sticker_interaction.py`: собственный стикер → смысловой comeback или короткий текст.
- Чужие стикерпаки игнорируются до обращения к sticker catalog.
- Свой стикер: 50% попытка смыслового ответа своим стикером / 50% короткий текст. Если хорошего контрстикера нет, даже «стикерная» половина падает обратно в текст, а не выбирает случайную картинку.
- Прямой вопрос: максимум 5% заменить ответ подходящим стикером; без semantic match — обычный текст; серьёзные вопросы исключены.
- Фоновый текст → стикер: после semantic match максимум 2%.
- Фоновый sticker anti-spam: минимум 10 минут по чату, 20 минут по пользователю, максимум 2 за час на чат.
- Жёсткие фоновые стикеры имеют ещё меньший шанс.
- Отдельный редкий `post-answer tag`: после полноценного текстового ответа бот может вторым сообщением поставить `БАЗА` или `ПЕРЕИГРАЛ И УНИЧТОЖИЛ`, только если смысл подходит.
- Live-проверкой уже обнаружены и убраны плохие связи вроде `ПО ДЕЛУ ГОВОРИ → БАЗА` и `ПЕРЕИГРАЛ И УНИЧТОЖИЛ → ЗА ДВИЖ`.
- `МИНУС АУРА → ПЛЮС АУРА` закреплён как осмысленный контрответ.

### Командные меню Telegram
- `command_menu.py` — единый источник меню для group/private/owner scopes.
- Группа показывает только утверждённый компактный список.
- Обычная личка показывает полезное ядро без группового развлекательного мусора.
- Владелец получает полное служебное меню в личке и owner-specific scope внутри групп.
- Обычным администраторам owner-меню не публикуется.
- BotFather вручную чистить не требуется: меню публикуются через `setMyCommands` на startup.
- `/help` теперь использует тот же источник данных, что и slash-menu: группа видит group help, личка — private help, владелец — полный owner help.
- Новый scoped `/help` стоит раньше legacy handler и останавливает дальнейшую обработку, чтобы не прилетало второе старое полное меню.

### Railway/PTB crash
- Исправлено падение из-за попытки писать custom instance attributes в slotted `telegram.ext.Application`.
- Runtime-состояние перенесено в module-level sets.
- После исправления и последующих стикерных/меню-коммитов Railway получал успешные deployments без старого crash-loop.

## 2. Автотесты / CI

Покрыто тестами:
- основные V2 engine/runtime блоки;
- все 37 ключей стикеров и их live-позиции;
- чужой sticker pack → ignore;
- граница 5% direct-question sticker;
- serious question → no sticker;
- background sticker <=2%;
- 50/50 own-sticker branch и semantic fallbacks;
- запрещённые нелогичные comeback-пары;
- primitive compact guard;
- group/private/owner command menus;
- scope-aware `/help` и Telegram 4096-char limit;
- daily title atomicity, один победитель в день, новый день, retry объявления;
- daily title persistence через повторную инициализацию БД (restart simulation).

Workflow `V2 CI` теперь запускает полный `pytest -q` и compile на **Python 3.12 и 3.13**, потому что production Railway работает на Python 3.13.

Важно: Railway deployment success не приравнивается к `PASS (CI)`. Полный GitHub Actions результат нужно считать подтверждённым только после зелёного workflow.

## 4. Что ещё нужно закрыть для текущего релиза
