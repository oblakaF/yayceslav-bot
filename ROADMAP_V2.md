# Яйцеслав V2 — дорожная карта и текущий статус

Обновлено: 2026-08-17
Рабочая ветка: `feature/human-yayceslav-v2`

Этот файл — единая точка фиксации того, что уже сделано, что прошло CI, что подтверждено живым Railway/Telegram и что ещё осталось.

## 1. Уже сделано

### Gemini / ответы
- Маршрутизация Gemini: основной `gemini-3.6-flash`, fallback на `gemini-3.1-flash-lite` при HTTP 429.
- После 429 тот же запрос сразу уходит на 3.1; 3.6 проверяется повторно после 30 минут.
- Cooldown сохраняется на Railway Volume.
- Компактный guard для hostile/challenge: короткие ответы, без простыней.
- Grammar-nazi режим для коротких несерьёзных сообщений: 25% шанс при реальной орфографической/грамматической ошибке.
- Rate-limit style guard скрывает технические сообщения ожидания от пользователя.

### Голосовые
- Входящее аудио обрабатывается напрямую Gemini без отдельной обязательной расшифровки.
- Ответ на голосовое ограничен примерно 180 символами.
- Таймкоды/служебные псевдотаймкоды удаляются.
- Для срача разрешена короткая многоуровневая схема setup → verdict → send-off.
- Серьёзные темы не переводятся в издёвку.

### Реакции / пассивное поведение
- Частота реакций снижена относительно прежней настройки.
- Рандомные текстовые вмешательства не должны плодить независимый спам-канал.
- Сохранены cooldown/ограничения hard-mode.

### Титулы
- Активные V2-пулы титулов вынесены отдельно.
- `/title` и `/title_status` зарегистрированы.
- Автоматический «титул дня» работает только в группах.
- Окно выдачи: после 18:00 МСК.
- Проверка scheduler: раз в 60 секунд.
- Один автоматический титул на чат в сутки; выбор среди участников, которые писали в этот день.
- Запись результата хранится в SQLite, чтобы рестарт не создавал второго победителя.

### Стикерпак
- Официальный набор опубликован: `https://t.me/addstickers/yayceslav_stickers`.
- В паке 29 стикеров.
- `/stickers` ведёт на официальный набор.
- `sticker_engine.py` содержит человечески редактируемую карту событие → стикеры.
- `sticker_interaction.py` содержит карту стикер → ответный стикер.
- Бот должен распознавать только собственный `yayceslav_stickers`; чужие наборы игнорируются.
- На прямой вопрос Яйцеславу: 5% шанс заменить текстовый ответ одним собственным стикером.
- Серьёзные вопросы исключены из 5% стикерного ответа.
- Фоновый текст → стикер ограничен максимум 2% даже после найденного события.
- Дополнительный антиспам фоновых стикеров: минимум 10 минут между фоновыми стикерами в чате, минимум 20 минут для одного пользователя, максимум 2 фоновых стикера за час на весь чат.
- Для собственного стикера `СКИЛЛ ИЩЬЮ` и остальных 28 есть заготовленная карта comeback-ответов из того же набора.

### Командные меню Telegram
- `command_menu.py` разделяет только отображение меню; скрытые команды из кода не удаляются.
- Обычная группа: короткое пользовательское меню.
- Обычная личка: полезное ядро без группового развлекательного мусора.
- Владелец: полное служебное меню в личке.
- Для владельца предусмотрено полное меню внутри каждой группы через `BotCommandScopeChatMember`.
- Обычным администраторам группы служебное owner-меню не показывается.
- BotFather вручную чистить не требуется: меню должны публиковаться через `setMyCommands` при старте бота.

### Railway/PTB crash — исправлено в коде
- Найдена реальная причина падения после добавления sticker runtime: попытка записать новые поля в `telegram.ext.Application`, который использует `__slots__` и не имеет `__dict__`.
- Убраны `_yayceslav_sticker_handlers_added` и аналогичные самодельные instance-атрибуты.
- Runtime-флаги перенесены в состояние модуля `sticker_runtime.py`.
- Добавлен регрессионный тест с настоящим PTB `Application`, который проверяет подготовку runtime без custom attributes и без дублирования handlers.

## 2. Что прошло CI

- Python compile.
- Основные тесты V2.
- Карта стикеров ссылается только на известные 29 ключей.
- Чужой стикер отклоняется до запроса sticker catalog.
- Граница 5% прямого вопроса проверяется детерминированно (`0.049999` — да, `0.05` — нет).
- Серьёзный вопрос не получает стикер даже при RNG=0.
- Все фоновые event chances не превышают 2%.
- Scoped command menus проверяются тестами.
- Owner group scope проверяется отдельно.
- Последний добавленный runtime regression для PTB `Application` проходит CI.

## 3. Что ещё НЕ считается подтверждённым до живого Telegram/Railway теста

Это важный список: зелёный CI не заменяет end-to-end Telegram.

1. После исправления `Application.__slots__` подтвердить, что Railway остаётся `Active` и больше не уходит в crash-loop.
2. Проверить в логах startup marker sticker runtime без `AttributeError`.
3. Отправить любой стикер из `yayceslav_stickers` боту в личку и убедиться, что он отвечает своим стикером.
4. Отправить `СКИЛЛ ИЩЬЮ` и проверить соответствие comeback-карте.
5. Отправить чужой стикерпак и убедиться, что реакции/ответа нет.
6. Проверить собственный стикерпак в группе. Если личка работает, а обычный стикер в группе нет — проверить Telegram Group Privacy Mode / права бота.
7. Проверить `/stickers` в личке и группе.
8. Проверить slash-menu обычного пользователя в группе.
9. Проверить slash-menu обычного пользователя в личке.
10. Проверить полное owner-menu владельца в личке и группе.
11. После 18:00 МСК проверить `/title_status` и фактическую автоматическую выдачу титула дня.
12. Проверить, что новый фон 2% действительно ощущается редким в живом активном чате; при необходимости снизить ещё.

## 4. Что осталось сделать после стабилизации runtime

### Приоритет A — закрыть текущий релиз
- Получить один стабильный Railway deployment без crash-loop.
- Провести end-to-end тест стикеров.
- Провести end-to-end тест scoped command menus.
- Провести end-to-end тест daily title.
- Сверить карту событие → стикер с владельцем и точечно поправить неудачные пары.

### Приоритет B — привести интерфейс команд к финальному виду
- Финально утвердить описания команд в group/private/owner меню.
- Решить, какие скрытые старые команды оставить доступными вручную, а какие позже реально удалить из кода.
- Проверить `/help`, чтобы он не рекламировал команды, которые скрыты из данного scope.

### Приоритет C — аккуратная эксплуатация стикеров
- По результатам живой недели оценить фактическую частоту: direct-question 5% и background <=2%.
- При необходимости добавить отдельный cooldown именно на sticker→sticker comeback, не меняя 5% вопросов.
- При необходимости добавить новые стикеры в пак и расширить карту без переписывания runtime.

### Приоритет D — косметика/брендинг
- Можно поменять отображаемое имя бота на «Яйцеслав» без изменения кода/данных.
- Вопрос изменения `@BOBR_KURWWA_bot` не смешивать с текущей стабилизацией; рассматривать отдельно после рабочего релиза.

### Приоритет E — безопасность/эксплуатация
- Если старый Telegram bot token когда-либо был виден в логах/скриншотах, после стабилизации убедиться, что он ротирован и Railway использует новый token.
- Не выводить token в пользовательские сообщения или диагностику.

## 5. Правило статусов

- `DONE (code)` — код написан и покрыт тестами.
- `PASS (CI)` — GitHub Actions зелёный.
- `CONFIRMED (runtime)` — подтверждено реальным Railway/Telegram запуском.

Текущий стикерный блок: `DONE (code) + PASS (CI)`, но до первого стабильного Railway запуска после исправления `__slots__` ещё не `CONFIRMED (runtime)`.
