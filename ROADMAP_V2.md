# Яйцеслав V2 — дорожная карта и текущий статус

Обновлено: 2026-08-19
Рабочая ветка: `feature/human-yayceslav-v2`

Этот файл фиксирует текущий релизный статус. `DONE (code)` означает, что код реализован; `PASS (CI)` — полный workflow завершился зелёным; `CONFIRMED (runtime)` — поведение проверено живым Railway/Telegram.

## 1. Реализовано

### Gemini / ответы
- Основной `gemini-3.6-flash`, автоматический fallback на `gemini-3.1-flash-lite` при HTTP 429.
- Тот же запрос после 429 сразу повторяется на 3.1; 3.6 пробуется снова через 30 минут.
- Cooldown хранится на Railway Volume.
- Hostile/challenge compact guard: короткие ответы без лекционных простыней.
- Primitive compact guard для простых запросов (`2+2`, `9*99`, `э`, `ну`, `чё`): короткий ответ; арифметический результат идёт первым.
- Grammar-nazi: 25% как дополнительный вариант только при реальной ошибке в коротком несерьёзном сообщении.
- Hostile anti-repeat хранит последние ответы конкретному человеку и запрещает точные/близкие повторы и одну и ту же центральную шутку несколько раз подряд.
- Короткие ping-pong реплики (`нет ты`, `сам такой`, `ты сам` и т.п.) считаются продолжением challenge/banter, а не новым normal-диалогом.
- Если первый hostile/challenge ответ слишком похож на недавний, Gemini получает одну повторную попытку; если и она повторная — используется короткий rotating fallback.
- В групповой перепалке general-rate-limit поднят до 12 обращений/минуту. При превышении ответ молча пропускается: служебный `пулемётчик` больше не должен вклиниваться в живой срач.

### Персональная память / социальный контекст
- Сохранён явный `/remember_me`: пользователь сам может попросить хранить безопасный долговременный факт.
- Добавлена автоматическая лёгкая callback-память по сообщениям конкретного пользователя. Она хранит только слова/короткие темы, которые написал именно этот человек, а не общий словарь чата.
- Исторические `chat_native_term_users` используются как стартовая выборка, поэтому вчерашнее упоминание Steam может естественно всплыть после деплоя.
- Автоматический callback не считается биографическим фактом: `Steam` означает «этот человек недавно упоминал Steam», а не автоматически «он всегда играет в Steam».
- Одноразовая тема живёт примерно 14 дней; повторяющаяся — дольше, но имеет hard TTL 180 дней. Память ограничена по размеру.
- После выбора callback-темы она получает 18-часовой cooldown, чтобы Steam/другая тема не становилась вечной пластинкой.
- Новые темы автоматически пополняют пул и вытесняют старые/слабые.
- Чувствительные медицинские/финансовые/политические/религиозные и сходные темы автоматом не сохраняются; фильтр применяется и к legacy backfill.
- Серьёзные темы не получают социальные callback-шутки.

### `/whoami`
- Старый сухой список заменён на короткое «досье Яйцеслава».
- Показываются статус знакомства, текущий титул, число сообщений, любимое слово (когда накоплена выборка), несколько недавних тем и динамический шуточный вердикт.
- Фото и голосовухи в `/whoami` специально не выводятся.
- Любимое слово считается per-user, с отсевом chat-native stopwords; точный исторический per-user count до внедрения этой функции восстановить нельзя, поэтому статистика становится точной с момента нового runtime.

### Титулы
- `/title` и `/title_status` зарегистрированы.
- Обычный автоматический титул дня: группа, окно после 18:00 МСК, scheduler раз в 60 секунд; кандидат должен писать в этот день.
- Победитель хранится в SQLite и переживает рестарт; повторная отправка не создаёт второго победителя.
- Добавлен отдельный **титул молчуна дня**: один известный активный участник с 0 сообщениями за последние 7 дней.
- Для молчунов отдельный пул (`Куколд-наблюдатель`, `Куколдини в режиме чтения`, `NPC в режиме AFK` и т.п.).
- Человек, который за всю известную боту историю имеет 0 сообщений, получает ещё более специальный never-spoke пул (`Верховный Куколдини`, `Невидимый участник`, `NPC без реплик` и т.п.).
- Silent-title хранится отдельно в SQLite: один на чат/день; при наличии альтернатив один и тот же молчун не выбирается снова в течение недели.
- Перед объявлением выбранный молчун валидируется через Telegram `get_chat_member`; ушедший участник исключается.
- Добавлен реестр membership. Известные старые профили backfill-ятся; новые входы/выходы и `CHAT_MEMBER` updates сохраняются.
- `allowed_updates` теперь дополняется `CHAT_MEMBER`, иначе Telegram не присылал бы события изменения состава.
- Ограничение Telegram: Bot API не предоставляет полную выгрузку всех уже существующих участников группы. Поэтому человек, который состоял в группе до внедрения реестра, никогда ничего не писал и никогда не дал member-update, не может быть обнаружен задним числом. С момента внедрения новые/изменившиеся участники учитываются.

### Стикерпак
- Официальный набор: `https://t.me/addstickers/yayceslav_stickers`.
- Финальный текущий размер пака: **37 стикеров**.
- Порядок всех 37 зафиксирован в `sticker_engine.py`.
- Старый `ИДИ ЛЕСОМ` удалён; вместо него `ИДИ НА ХУЙ!`.
- Свой стикер: 50% попытка смыслового ответа своим стикером / 50% короткий текст. Если хорошего контрстикера нет, ответ текстом.
- Чужие стикерпаки игнорируются.
- Прямой вопрос: максимум 5% заменить ответ подходящим стикером; серьёзные вопросы исключены.
- Фоновый текст → стикер: после semantic match максимум 2%; действуют chat/user/hour cooldown.
- Отдельный редкий `post-answer tag`: после текста может идти `БАЗА` или `ПЕРЕИГРАЛ И УНИЧТОЖИЛ`, только по смыслу.

### Командные меню Telegram
- `command_menu.py` — единый источник group/private/owner scopes.
- `/help` использует те же scopes и не должен рекламировать скрытые команды.
- Владелец получает полный служебный набор, обычная группа/личка — свои компактные меню.

### Railway/PTB
- Исправлено старое падение из-за custom attributes на slotted `telegram.ext.Application`.
- Новые runtime-патчи также используют module-level state/классовый wrapper и не добавляют поля в экземпляр `Application`.

## 2. Автотесты / CI

Покрыто тестами:
- основные V2 engine/runtime блоки;
- 37 стикеров, semantic comeback/fallback, direct/background chances;
- primitive compact guard;
- scoped command menu и `/help`;
- daily-title persistence/restart/retry;
- per-user callback memory и 18h rotation;
- per-user favorite word;
- отказ автоматической памяти от чувствительных тем;
- legacy-memory safety purge;
- week-silent и never-spoke кандидаты;
- один silent-title на чат/день;
- hostile exact-repeat и повтор центральной темы;
- короткие `нет ты`/`сам такой` как banter follow-up.

Workflow `V2 CI` запускает compile + `pytest -q` на Python 3.12 и 3.13. Railway deployment success не приравнивается к `PASS (CI)`.

## 3. Уже подтверждено живым Telegram/Railway

- Gemini 3.6 → 3.1 fallback после 429.
- Railway после PTB `Application.__slots__` fix не падает по старой причине.
- Свой стикерпак распознаётся; новый порядок 37 используется.
- Sticker→sticker и sticker→text ответы работают.
- Primitive compact ответы стали короче.
- Живые скрины выявили проблему повторов hostile-ответов и служебного rate-limit текста; соответствующие исправления добавлены, но их нужно отдельно проверить после нового деплоя.

## 4. Что ещё нужно проверить живьём

1. Hostile-разговор: подряд `нет ты`/`сам такой` не должен повторять один и тот же ответ или одну тему вроде «интеллект».
2. Быстрый групповой banter: первые 12 general-обращений/мин не должны выдавать `Полегче, пулемётчик`; после лимита лишнее молча пропускается.
3. Через день/два проверить callback на старую тему (например Steam): он должен быть редким и естественным, затем тема уходит на cooldown и заменяется другими.
4. `/whoami`: проверить любимое слово/вердикт на реальной накопленной статистике.
5. После 18:00 МСК проверить обычный титул дня и отдельный титул молчуна.
6. Проверить участника, который не писал неделю; отдельно — нового/изменившего membership человека с 0 сообщений.
7. Scoped `/help` + slash-menu group/private/owner.
