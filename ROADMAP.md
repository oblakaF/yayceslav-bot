# 1. Главная концепция бота

**Яйцеслав — постоянный участник группового чата со своим характером, а не набор разрозненных команд.**

Он должен:

- понимать недавний контекст переписки;
- применять команды к уже написанным сообщениям;
- помнить участников и безопасные факты о них;
- спорить, рассуждать, прожаривать и анализировать;
- искать актуальную информацию в интернете;
- пересказывать разговор и продолжать коллективную историю;
- вести статистику группы;
- отвечать в характере самоуверенного ироничного древнего руса;
- становиться серьёзным на чувствительных темах;
- не заставлять пользователя заново копировать тему после каждой команды.

Главный пользовательский сценарий:

```text
Пользователь: Сейчас в фильмах слишком много повестки
Пользователь: /judge
Бот: анализирует предыдущее сообщение и выносит вердикт
```

Команда должна работать как действие над контекстом, а не только как команда с обязательными аргументами.

# 2. Неприкосновенные требования

1. Не ломать уже работающие функции: обычные ответы, голос, фото, документы, поиск, настройки, память группы и хард-мод.
2. Административные команды должны быть доступны только разрешённым ролям.
3. Групповой администратор не получает права владельца бота автоматически.
4. Не хранить полные тексты всей переписки, документы, изображения, голосовые файлы и ответы Gemini в постоянной базе.
5. Учитывать лимит Railway Volume: 500 МБ.
6. Секреты и API-ключи хранить только в Railway Variables или локальном `.env`.
7. Крупные функции включать через feature flags, когда это оправдано.
8. Перед деплоем запускать тесты и проверку импорта.
9. SQLite-миграции должны быть неразрушительными.
10. Один небольшой этап — один осмысленный коммит.
11. Не переписывать одновременно все команды без промежуточных тестов.
12. Не менять характер, статистику и БД одной смешанной правкой.

# 5. P1 — единая логика контекстных команд

## P1-01. Общий источник текста команды

**Статус: 🟡 ЧАСТИЧНО** (commit `46bc552`) — реализовано как функция `resolve_topic_text()` в `bot.py` (не отдельный модуль `context_service`/`command_context.py`, как предполагалось изначально, но с тем же эффектом единого источника истины).

Создать один `context_service` или `command_context.py`. Все текстовые команды обязаны использовать его.

### Утверждённый приоритет

1. Сообщение, на которое пользователь ответил командой.
2. Текст, написанный после команды.
3. Последнее обычное сообщение этого пользователя.
4. Для групповых аналитических команд — последнее подходящее сообщение группы.
5. Только при полном отсутствии контекста показать подсказку.

### Дополнительные правила

- [x] не использовать другую команду как исходный текст (`record_last_user_message` вызывается только из обработчиков обычных текстовых сообщений, не из `CommandHandler`, `bot.py:5971,7819,7882`);
- [x] не использовать сообщение самого бота (Telegram не присылает боту его же исходящие сообщения как `update.message`);
- [ ] не использовать служебные события Telegram — не проверялось отдельно;
- [ ] не использовать пустые подписи и стикеры без текста — `resolve_topic_text` проверяет `reply_to_message.text`, но стикеры/подписи отдельно не тестировались;
- [x] не брать очень старое сообщение (`LAST_USER_TEXT_MESSAGE_MAX_AGE_SECONDS`);
- [x] рекомендуемый TTL последнего сообщения: 30–60 минут (ровно 30 минут, `bot.py:5764`);
- [x] хранить только ограниченный краткий контекст (только текст последнего сообщения, не история);
- [x] память одного чата не должна попадать в другой чат (ключ `(chat_id, user_id)`, `GROUP_MEMORY` ключ `chat_id`);
- [ ] одна команда не должна реализовывать свой отдельный несовместимый алгоритм — **не выполнено**: `/roast` не вызывает `resolve_topic_text()`, а инлайнит эквивалентную, но отдельную логику (`bot.py:4229-4247`).

## P1-02. `/argument`

**Статус: 🟡 ЧАСТИЧНО** (commit `46bc552`) — новая логика реализована и не требует Telegram-проверки для базовой корректности, но раздел остаётся 🟡 до ручной проверки в группе.

Текущая команда умеет сравнивать две позиции, но требует reply и вторую позицию после команды. Это не соответствует новой идее.

### Новая логика

Пользователь пишет:

```text
Земля
/argument
```

Бот случайно выбирает:

- поддержать исходную мысль;
- возразить ей.

Примеры желаемого характера:

```text
Земля плоская. Юрий Лоза давно всё доказал, а глобусы печатает мировой заговор.
```

или:

```text
Земля круглая, мыслитель. Спутники, кругосветные маршруты и даже школьный глобус справились с этой темой раньше тебя.
```

Шуточная ложная позиция должна явно восприниматься как юмор.

### Чек-лист

- [x] работает по reply (`resolve_topic_text`, `bot.py:4566`);
- [x] работает по тексту после команды;
- [x] работает по последнему сообщению пользователя;
- [x] не требует обязательную вторую позицию (только если reply + args одновременно — тогда старый режим «спор двух позиций»);
- [x] случайно выбирает «за» или «против» (`random.choice(ARGUMENT_POSITIONS)`, `bot.py:4575`);
- [ ] содержит хотя бы один понятный довод — задано в промпте, не проверено тестом на реальном ответе Gemini;
- [x] добавляет короткий подкол Яйцеслава (в промпте: «с коротким подколом в конце»);
- [x] размер: примерно 2–4 небольших абзаца (промпт явно требует «Два-четыре небольших абзаца»);
- [ ] серьёзные темы не превращает в абсурдную шутку — не проверяется `is_serious_text`, риск остаётся;
- [x] старый режим сравнения двух позиций сохранён как отдельная явная ветка (reply + args вместе), не удалён.

Содержат смысловую логику команд.

#### `repositories/`

Содержат только работу с SQLite.

#### `personality/`

Содержит характер, режимы, классификацию намерения и правила юмора.

#### `data/`

Содержит словари и наборы фраз без Telegram и SQLite.
