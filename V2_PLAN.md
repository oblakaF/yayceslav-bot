# Яйцеслав V2 — план реализации

База: `feature/human-yayceslav`.
Рабочая ветка: `feature/human-yayceslav-v2`.

## Жёсткие правила V2

1. V1 не изменяется: все эксперименты и новые механики идут только в V2.
2. Один ответ — один речевой стиль. Никакого смешивания youth/skoof/old-russian/blat/operative/battle/post-irony в одной реплике.
3. Серьёзные и чувствительные темы всегда подавляют агрессивные/мемные стили.
4. Полезность ответа выше персонажа: если нужен точный ответ, сначала факт/решение, затем характер.
5. Новые механики вводятся этапами и покрываются тестами до следующего этапа.

## Этап 1. Единый селектор речевого стиля

- [ ] Ввести единый `voice_pack` на ответ.
- [ ] Пакеты: `classic`, `youth`, `skoof`, `old_russian`, `blat`, `operative`, `battle_2017`, `post_irony`.
- [ ] `operative` — скрытый редкий стиль, не отображается в пользовательских настройках.
- [ ] `serious` всегда принудительно использует безопасный нейтральный стиль.
- [ ] Запретить выбор слов из чужого пакета после фиксации `voice_pack`.

## Этап 2. Динамическая длина и антизанудство

- [ ] Классы длины: `micro`, `short`, `normal`, `long`.
- [ ] Выбор длины зависит от контекста и немного рандомизируется.
- [ ] `short/normal/detailed` пользователя — bias, а не жёсткий размер.
- [ ] Хранить последние классы длины по чату и избегать одинакового ритма.
- [ ] После длинного ответа повышать вероятность короткого (`verbosity fatigue`).
- [ ] На простые вопросы разрешить ответить одной-двумя фразами и остановиться без лишних пояснений.

## Этап 3. Подключение уже существующих, но неактивных механик

- [ ] Подключить `RUNET_2007`, `RUNET_2012_2016`, `LAN_GAMING_2000S`, `RUSSIAN_INTERNET_CLASSICS`, `OLD_RUSSIAN_METAPHORS`.
- [ ] Реализовать отдельную обработку заявленных типов юмора: `irony`, `hyperbole`, `gaming_terminology`, `deadpan_official`, `anti_joke`, `comic_refusal`.
- [ ] Реально передавать `callback_reference` в инструкцию Gemini.
- [ ] Использовать `selected_address`, `last_humor_strategy` и другие уже предусмотренные поля там, где они действительно нужны.

## Этап 4. Персонализация поведения

- [ ] Передавать `relationship_level` в HumorContext.
- [ ] Использовать текущий титул участника в редких callback-подколах.
- [ ] Использовать заданный админом `joke_archetype` в редких персонализированных шутках.
- [ ] Не делать постоянную вендетту: конфликтная память краткосрочная и затухает.

## Этап 5. Мат и агрессивность

- [ ] Разделить `roughness` (лексика/мат) и `aggression` (желание спорить/цепляться).
- [ ] Убрать искусственное ограничение `high = одно ругательство`.
- [ ] В несерьёзных режимах разрешить более естественный мат, не превращая каждый ответ в поток ругани.
- [ ] Добавить `dokop`-механику: иногда цепляться к явному противоречию, самоуверенной ерунде или слабому аргументу.
- [ ] В споре помнить 1–2 предыдущие реплики и продолжать линию, а не начинать конфликт с нуля.
- [ ] Cooldown на инициативное докапывание, чтобы не преследовать одного участника.

## Этап 6. Блатной пакет

- [ ] Отдельный `blat` voice pack без смешивания со всеми другими стилями.
- [ ] Пулы: slang, addresses, taunts, rough, flex, comebacks, wisdoms, grumbling, praise, comparisons, greetings.
- [ ] Речь в духе комедийного уголовно-блатного жаргона: `базар`, `рамсы`, `кипиш`, `фраер`, `кент`, `бродяга`, `понты`, `малява`, `расклад`, `предъява`, `отвечай за базар`, `фуфло` и т.п.
- [ ] Никаких реальных инструкций по преступлениям.

## Этап 7. Скрытый оперативный пакет

- [ ] Отдельный редкий `operative` voice pack.
- [ ] Сухая пародия на КГБ/ФСБ/служебную бюрократию: `всё записано`, `материал подшит`, `информация ушла куда следует`, `протокол составлен`, `это штраф`.
- [ ] Никогда не утверждать, что бот реально связан со спецслужбами или реально передаёт данные.
- [ ] Не использовать шутки с реальной угрозой сексуализированного/физического насилия.

## Этап 8. Battle 2017

- [ ] Отдельный `battle_2017` voice pack.
- [ ] Только короткие общеизвестные мемные микро-референсы, без длинных чужих раундов.
- [ ] Проверенные мемы: `изи-изи`, `рил ток`, `синк эбаут ит`; дополнительные фразы — только после проверки источника.
- [ ] Основной контент — оригинальные панчи Яйцеслава в баттл-манере, а не копирование чужого текста.

## Этап 9. Постирония

- [ ] Отдельный `post_irony` voice pack без смешивания.
- [ ] Сухая мета-постирония: fake expertise, overreaction, underreaction, deadpan, meta-comments.
- [ ] Не объяснять каждую шутку и не ставить обязательный смайлик/`шучу`.
- [ ] Не копировать голос/фразы конкретного живого автора; сделать самостоятельный стиль интернет-постиронии.

## Этап 10. Умные emoji

- [ ] Снизить именно emoji-реакции примерно на 20%; текстовые random replies этим множителем не резать.
- [ ] Выбирать emoji по причине/intent, а не только из общего случайного пула.
- [ ] Расширить context mapping для аргументов, провокаций, абсурда, мистики и т.п.

## Этап 11. Random drops

- [ ] Пассивные редкие вмешательства в активной группе без обращения к боту.
- [ ] Не жёстко «каждое N-е сообщение», а окно вероятности после накопления активности.
- [ ] Один random drop — один voice pack.
- [ ] Использовать существующий anti-repeat tracker.

## Этап 12. Fatigue

- [ ] При частых вызовах за короткий период иногда добавлять короткое ворчание.
- [ ] После срабатывания — cooldown.
- [ ] На серьёзных темах полностью отключать.

## Этап 13. Daily title

- [ ] Раз в сутки случайный активный участник получает титул через существующую систему `/title`.
- [ ] Не повторять предыдущий титул.
- [ ] Хранить результат в SQLite и переживать рестарт.
- [ ] Разрешить редкий callback на текущий титул.

## Этап 14. State machine

- [ ] Довести состояния `cold_start`, `warming_up`, `normal`, `hostile_response`, `serious`.
- [ ] Добавить краткосрочные `annoyed` и `argumentative`.
- [ ] Состояние влияет на вероятность агрессии/длины/инициативы, но не ломает правило одного voice pack.

## Отложено

- Реакция «меня проигнорировали» — не внедрять пока.
- Не делать `unhinged` дефолтом.
- Не смешивать стили ни при каких обстоятельствах.
